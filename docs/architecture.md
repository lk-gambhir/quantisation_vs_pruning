# Project architecture

## Layout

```text
ml_project/
├── README.md
├── agents.md                 instructions for anyone (or any assistant) continuing the project
├── requirements.txt          pinned package versions used for the recorded results
├── notebooks/
│   └── start.ipynb           main notebook: runs the full study and shows the results
├── src/
│   ├── config.py             all shared settings (seeds, training, variants, benchmark)
│   ├── data.py               dataset loading, seeded split, loaders
│   ├── model.py              the MLP and parameter count
│   ├── train.py              seeding, epoch loop, validation-loss checkpoint selection
│   ├── compress.py           pruning, INT8 quantization, sparsity, artifact save/reload
│   ├── evaluate.py           predictions, accuracy/F1, per-class metrics, confusion matrix
│   ├── benchmark.py          CPU latency measurement and p50/p95/IQR summary
│   └── plotresults.py        every figure, drawn from saved tables
├── data/                     Fashion-MNIST cache (downloaded on first run, not committed)
├── outputs/                  generated by the notebook (see below)
└── docs/                     project documentation
```

The notebook is the entry point and holds no reusable logic. Each `src/` module has one responsibility and is imported by the notebook. All settings live in `src/config.py`, so every seed and variant runs the same procedure.

## Data and model flow

```text
Fashion-MNIST (official train / test)
  → per seed: seeded 90/10 train/validation split          data.py
  → train FP32 baseline, keep lowest-validation-loss epoch  train.py
  → derive 7 variants independently from that baseline      compress.py
  → save each as model.pt, reload, check predictions match  compress.py
  → evaluate the reloaded file on the full test set         evaluate.py
  → time the reloaded file on CPU                           benchmark.py
  → aggregate across seeds, apply decision rule             notebook
  → draw figures from saved tables                          plotresults.py
```

The variants are `fp32`, `pruned30`, `pruned50`, `pruned70`, `pruned90`, `int8` and `pruned50int8`.

## Generated outputs

```text
outputs/
├── setup.json                 software versions, CPU, INT8 engine, benchmark threads
├── dataset-summary.json       counts per class, image shape, pixel range
├── runs/
│   ├── config.json            frozen settings used for this run
│   └── seed<N>/
│       ├── split.json         exact train and validation indices
│       └── history.csv        per-epoch train/validation loss and accuracy
├── checkpoints/seed<N>/<variant>/model.pt    inference-only state dictionaries
├── metrics/
│   ├── results.csv            one row per seed × variant: sparsity, accuracy, F1, bytes, deltas
│   ├── summary.csv            mean/SD across seeds plus latency, the main table
│   ├── perclass.csv           precision/recall/F1 per class, seed and variant
│   ├── layersparsity.csv      zeros and dead neurons per layer
│   ├── comparisons.csv        test examples that change between FP32 and each variant
│   ├── latency.csv            p50/p95/IQR per seed, variant and batch size
│   ├── latency-raw.csv        every timed iteration
│   ├── history.csv            all seeds' training histories
│   ├── failures-seed42.csv    IDs of examples FP32 gets right and a variant gets wrong
│   ├── predictions/seed<N>.csv  per-example label and prediction of every variant
│   └── confusion/seed<N>-<variant>.csv
└── figures/                   samples, learning curves, trade-off plots, diagnostics
```

## Artifact rules

- Artifacts are inference-only state dictionaries. Optimizer state and training history are never included.
- Every artifact is named `model.pt` in its own folder. `torch.save` writes the file name into the archive, so the same name keeps byte counts comparable. In the pilot, `pruned_90.pth` was 12 bytes larger than `baseline.pth` for this reason alone.
- Every reported metric and timing comes from the file after reloading it, and the reloaded predictions are checked against the in-memory model.
- Sizes are reported in bytes. Where kB appears, 1 kB = 1,000 bytes.
- `data/`, `.venv/` and `outputs/checkpoints/` are listed in `.gitignore`. The checkpoints can be recreated by running the notebook.
